# 画布区方案：复用工程画布 · 自由生图

> 状态：v2（经 2026-10-31 代码可行性审阅修订，连线语义定案见 3.2 / 决策 6） · 日期：2026-10-31
> 关联：工程画布 `src/pages/ResourcePage/ProjectCanvas.tsx` · sheengo-canvas `services/api`（协议参考）

## 一、背景与目标

资源库的工程视图已有一套成熟的无限画布（节点、连线、框选、多选、撤销、便签、分组），
但它只做**展示与编排**——素材挂接关系可视化，生成动作仍在外部 AI 工具完成后再拖回来。

新需求：在侧栏新增第四个顶级区「**画布**」，一个**能直接生图**的自由工作流画布：

- 复用工程画布已验证的画布引擎与交互手势，不重造轮子；
- 叠加 AI 生图能力：摆提示词、挂参考图、连线、点击生成、多图备选；
- 生成产物直接落入资源库，与工程视图形成闭环
  （自由创作 → 素材沉淀 → 工程编排）；
- 完全融合：UI 沿用 iOS 磨砂玻璃风格，数据落 SQLite。

一句话定位：**工程画布是展示板，画布区是生产车间**。

参考项目 sheengo-canvas（用户自有 Web 项目）提供 AI 调用协议层的领域知识
（OpenAI 兼容 images API、Gemini 原生接口、尺寸映射、参考图组装规则）。

## 二、与现有工程画布的关系

| 维度 | 工程画布（现有） | 画布区（新） |
|:---|:---|:---|
| 数据锚 | 剧集结构（集/场景/镜头） | 画布自身（多画布，与剧集无关） |
| 连线语义 | 片段端口级（六口分色，端口即生成链输入位） | **节点级引用**（上游产物 = 下游输入） |
| 节点来源 | 工程 overview（镜头/资料/剧本/成片） | 画布自建节点（文本/图片/参考图/便签） |
| 生成动作 | 无（仅编排） | 节点内直接调用 AI 生图 |
| 存储 | 工程表 + 按集 localStorage 覆盖层 | 画布三表，位置/视口/尺寸全部入库 |

### 复用清单（从 ProjectCanvas 搬入基座）

- 视口变换：平移 / 缩放 / 滚轮缩放 / 迷你地图
- 连线渲染：`wirePathD` 贝塞尔 + `nodeMetrics` 节点实测锚点跟随
- 连线手势全套：拖线建连（吸附近位）→ **摘线换目标**（含出生锚点重挂）→
  Shift+右键划线切线 → 拖线到空白弹建节点菜单并自动接回
- 框选 / 多选 / 多选组拖 / Ctrl+C/V 复制粘贴 / Ctrl+Z 撤销栈
- 双击空白建节点菜单、节点右下角尺寸手柄、出生锚点脉冲动画
- 便签节点、Ctrl+G 节点分组、Delete/Backspace 删除选中（输入框聚焦与弹层打开时不响应）
- 节点类型色通道、选中点亮描边、亮暗双主题适配、连线层视口裁切（WIRES_VIEWPORT_PAD）

> **审计边界（2026-10-31 实测，5940 行）**：真引擎级约 20%（`wirePathD`、
> `measureNodes` 盒测量、`outPointOf`、视口/平移缩放、框选机制、尺寸手柄、
> 切痕层、SVG 视口层、双击判定、便签、nodeGroups）——这部分零改动搬。
> 上表「连线手势全套」复用的是**手势骨架**（拖线状态机、松手判定
> `resolveWireRelease` 纯函数），而落点识别 / 吸附 / 接回 / 落库是端口级
> 实现，须按节点级语义重写（见 3.3 改造点 1）；迷你地图与 fitAll 的包围盒
> 枚举也是工程域集合，数据源随节点类型重写；切线实际触发为 Shift 或
> Ctrl+右键。

### 剥离清单（工程域专属，不进基座）

- useProjectStore / episodeId / overview 数据源、usePerEpisodeStorage 按集存取
- 场景框、镜头卡、剧本纸片、成片输出节点、缺项提醒、默认工作流模板
- 端口分色六口体系（新画布无端口语义）、资料组认领/顶掉逻辑（新画布无资料组
  语义，连线同源去重见 3.2）

### 有意简化（相对工程画布）

- 连线从「端口级」降为「节点级」：每节点右侧一个输出口、左侧一个输入位，
  连线即"引用上游"。摘线/切线/建节点接回手势原样保留，落点从端口变为节点。
- 资料组（一个节点多实体）不做；多图备选由图片节点自身承担。
- 撤销栈范围：对齐基座现状——移动 / 尺寸 / 粘贴 / 可完整恢复的删除；
  **连线不入撤销栈**（基座 link/unlink 本就不入栈，一期不新增），连线误操作
  用摘线 / 切线手势修正，连线撤销列入第七节演进；生成结果不进撤销栈
  （生成不可撤销，重试即覆盖，见 3.4 成本防护）。

## 三、总体架构

### 3.1 顶级区挂载与页面骨架

- `App.tsx`：`NAV_ITEMS` / `PANEL_MAP` 增加第四项 `canvas`，i18n `tabs.canvas`
  （中英同步，遵守 i18n 守卫「键名禁含点号」断言），侧栏图标 palette 系；
  沿用面板保挂载策略（切区不重载）。
- 页面骨架 `src/pages/CanvasPage/`（与 ResourcePage 平级）：
  - 顶部画布库条：画布 chips（按 updated_at 倒序）+ 新建 + 每画布「⋯」菜单
    （重命名 / 删除）；chips 放不下时收进「更多」，与资源页分组条同款处理；
  - 主画布 + 右侧属性面板（选中节点参数编辑；图片节点含「生成」按钮）；
  - 切换画布 = 同一组件重载数据（不为每画布挂一个实例），视口按 canvas_id
    从库恢复；删除画布走 ConfirmDialog 确认，文案注明「节点与连线一并删除，
    已存入资源库的图片不受影响」。

### 3.2 数据层（SQLite 三表）

仿 `db/project.rs` 域模式，新增 `db/canvas.rs`：

```
canvases            画布：id(TEXT PK) / name / viewport_x / viewport_y / viewport_k
                    / created_at / updated_at
canvas_nodes        节点：id(TEXT PK) / canvas_id / type(text|image|ref|note) / title
                    / pos_x / pos_y / width / height / metadata(JSON) / resource_path
canvas_connections  连线：id(TEXT PK) / canvas_id / from_node / to_node
                    / created_at（多提示词拼接排序键）
                    / UNIQUE(canvas_id, from_node, to_node)  ← 仅防同源重复平行线
canvas_list         （视图或查询）画布 + 节点数 / 连线数聚合，供画布库条显示
```

关键设计：

- **metadata 是严格类型的 JSON**：Rust 端按节点类型定义 serde 结构
  （`NodeMeta::Text{content}` / `NodeMeta::Image{params, status, error, images[]}`
  / `NodeMeta::Ref{...}` / `NodeMeta::Note{content}`），拒绝自由袋子腐化；
  前端 TS 类型与 serde 一一对应，字段增删走 ensure_column / serde default 幂等升级。
- **连线语义定案（v2，废止 v1 的「输入位唯一来源」）**：连线多入线、按类型
  分组累积——text 多线按 `created_at` 顺序拼接为提示词，ref/图片多线累积为
  参考图（图片取主图）；`UNIQUE(canvas_id, from_node, to_node)` 仅防同源
  重复平行线。v1 的 `UNIQUE(canvas_id, to_node)` 与 3.6 多提示词拼接直接
  矛盾，且「UNIQUE 天然顶掉」对工程画布现状的描述本就失真（工程域落表是
  `INSERT OR IGNORE`，顶掉实为前端 unlink+link）。摘线换目标 = 改写该线
  to_node，不再有顶掉。
- id 由后端生成（对齐工程域惯例，uuid v4）；CRUD 命令 + `canvas-changed` 事件
  （对齐 `project-changed`：`app.emit` 广播空载荷）；`ensure_column` 幂等升级；
  三表登记 `MIGRATED_BUSINESS_TABLES`；Rust 测试覆盖
  迁移 / CRUD / 同源去重 / metadata serde 往返。
- **备份（已核实）**：`backup.rs` 为 `VACUUM INTO` 整库快照，三表自动纳入
  导出与恢复；但换存储目录迁移的 `MIGRATED_BUSINESS_TABLES` 清单需显式登记
  三表，漏登记有守卫测试拦截。

### 3.3 画布基座（fork 与改造）

以 ProjectCanvas 为基座 fork 出 `CanvasPage/FreeCanvas.tsx`，按第二节清单
剥离工程域、替换数据源。关键改造点：

1. **数据源换血 + 连线子系统重写**：镜头/资料/剧本的渲染模型换成 canvas_nodes
   四类节点；视口、手势状态机、框选、尺寸手柄、切痕层等引擎框架**零改动搬**
   （只动数据从哪来），为日后双份维护与修复回灌留最小 diff；但连线子系统
   （portsOf / inPointOf / 拖线吸附 / 摘线识别 / autoConnectNewNode /
   finishDetached / nodeKeyParts / 切线分发 + PendingLink / LiftedWire /
   DragState / 线色体系）按节点级语义重写——端口身份渗透约 19 处，这是
   阶段 1 的主要工作量。节点 key 前缀体系沿用（note:/text:/image:/ref:）；
   默认工作流模板 effect 必须整体移除，否则新建画布写脏数据；出生锚点脉冲
   从「仅资料节点」通用化到新建节点。
2. **localStorage → DB**：视口、便签、位置、尺寸全部改走 canvasStore（SQLite）。
   防抖自建：工程画布实为松手一次性落盘、无防抖（视口每滚一步即写
   localStorage），照搬会变成每滚一步写库——落库统一防抖批量（视口/位置/
   尺寸同批），松手落盘时机保留。
3. **连线落库**：拖线松手写 `canvas_connections`（同源重复由
   UNIQUE + INSERT OR IGNORE 去重）；摘线换目标 = 更新该线 to_node；
   切线按连线 id 删行。
4. **fork 提交纪律**：剥离遵循「先删后改、小步可验」——fork 副本先跑通空画布
   （平移缩放/建节点/连线），再逐类接节点；每完成一个可独立验证的子步骤即提交，
   typecheck 是剥离完整性的机械守门员。

> 备选方案（不采用，记录理由）：抽共享画布内核组件让两边组合复用。
> ProjectCanvas 与工程域耦合深，抽内核是一次大手术且回归风险集中；
> fork 路线见效快、风险可分步消化。三期结束后评估是否收敛（见第七节）。

### 3.4 生图链路（Rust 全转发）

**已确认决策：协议层用 Rust 重写，Key 存 SQLite 不进前端。**

- **配置**（设置页新增「AI 生图」区）：
  - OpenAI 兼容：API Key、Base URL（默认官方，支持中转站）；
  - Gemini：API Key、Base URL（默认官方，支持中转域名）；
  - 默认模型、请求超时秒数；存 `settings` 表。
- **请求**：新增 `src-tauri/src/ai.rs`，命令
  `ai_generate_image(canvas_id, node_id, params)`；HTTP 客户端需新增依赖
  （Cargo.toml 现无任何 HTTP 客户端，建议 reqwest + rustls，双平台免系统
  依赖）；`base64` / `image 0.25` 已在，产物尺寸校验与缩略无需新依赖：
  - OpenAI 兼容：`POST {base}/images/generations`（文生图）、
    `/images/edits`（参考图编辑，multipart）；
  - Gemini 原生：`POST {base}/models/{model}:generateContent`
    （inlineData 参考图，无官方 n 参数时 Rust 侧并发多请求）；
  - 协议细节（尺寸→像素映射、比例清单、参考图组装规则、错误语义）
    从 sheengo-canvas `services/api/image.ts`（921 行）翻译，行为等价；
    翻译时为每条规则补 Rust 单测（请求体组装 / 尺寸映射 / 错误解析，mock 响应）；
  - **并发与逐张回传**：单次生成并发上限 4，每张完成即发
    `canvas-generation-progress` 事件（node_id + 槽位 + base64），
    前端槽位逐格填充；全部完成后一次性落库（避免中途退出留下半批孤儿文件）；
  - **取消**：生成中可取消（AbortId），已完成的张数正常保留。
- **成本防护**（生图是计费操作）：
  - 失败**不自动重试**，重试一律手动点按钮；
  - 生成按钮旁常显「模型 · 数量」摘要，用户对每次点击花什么有数；
  - 超时可配，默认值保守（60s）。
- **Key 安全（诚实声明）**：一期 Key 明文存本机 SQLite（与 sheengo-canvas
  存 localStorage 同级安全，桌面单用户场景可接受）；Key 不进前端内存、
  不进日志、不进 canvas-changed 等事件载荷。加密存储（DPAPI/keyring）列入
  后续可选演进（第七节）。
- 一期不搬：流式 SSE、function calling 工具循环、自定义调用脚本、生视频/音频。

### 3.5 产物与参考图统一入库

- **生成产物**：写资源库「画布产物」分组（无则自动创建），复用
  `import_file_into_library` 纯入库函数（与挂靠选择器同款登记链路；已核实
  只收文件路径——base64 产物先写临时文件再传入；入库即同步登记资源记录并
  bump 修订号，前端轮询即刻可见，不依赖 watcher fs 事件；重名「 (n)」序号
  内置）；文件命名 `画布名-节点名-时间戳.png`；
- **参考图同理**：从资源库选/拖 = 路径引用；从电脑上传 = 先复制进库
  （「未分组」，重名加序号）再引用——**一切参考图都先进资源库**，
  内容即文件哲学一个出口，节点只记 `resource_path`；
- 图片节点 `metadata.images[]` 记录每张备选的宽高 / 字节 / `resource_path` /
  `primary` 标（**主图语义**：下游引用图片节点时取主图，卡片点备选可切换主图）；
- 卡片底部「已存入资源库」行 + 「在资源库中显示」直达（复用 openResourceFile
  定位选中）；删除画布 / 删除节点只删画布域数据，**不删资源库文件**；
- 闭环收益：画布产物可被工程视图挂靠到镜头（既有能力，零成本打通）。

### 3.6 交互细节契约

- **多提示词拼接**：允许多个文本节点连线到同一图片节点（多入线），按连线
  `created_at` 顺序以换行拼接为最终提示词；引用 chips 带序号显示，生成前在
  面板可预览拼接结果；同一对节点的重复连线被 UNIQUE 去重；
- **生成输入收集**：自身参数 + 上游引用（text→提示词，ref/图片→参考图，
  图片取主图）；无任何提示词来源时生成按钮禁用并提示；
- **节点双击**：文本/便签节点进编辑；图片节点打开大图预览（备选切换）；
  ref 节点打开资源详情（复用既有详情页能力）；
- **空态**：新画布首入给一张「最小工作流」示意（提示词→生图），一键生成示例
  节点，参考工程画布默认工作流模板惯例，落库后不再重建；
- **缩略图**：画布内图片走 media_server，带 updated_at 版本参数防缓存陈旧；
  大图加载与资源库缩略图体系对齐，必要时 media_server 增 resize 参数（阶段 2 核实）。

## 五、风险与对策

- **fork 双维护**：画布引擎两份，通用 bug 要修两处。对策：fork 时引擎框架
  零改动搬（只动数据源层，连线子系统重写除外），通用修复以小步提交同步回灌，
  CHANGELOG 注明。
- **基座剥离与连线重写工作量**：实测 5940 行（v1 写 5896 系旧快照），工程域
  约占八成（删），而连线子系统约 19 处端口渗透须重写——阶段 1 大头在重写

## 六、已确认决策记录

1. 形态：AI 工作流画布（自由摆放节点 + 连线 + 生图），非手绘白板。
2. 一期范围：编排 + 生图（OpenAI 兼容 + Gemini）；视频/音频/遮罩编辑后接。
3. 融合方式：完全融合——玻璃风格重写 UI、数据落 SQLite、产物直接落资源库。
4. AI 请求通道：Rust 全转发，Key 存 SQLite 不进前端。
5. 画布基座：复用工程画布（fork 剥离），不另起炉灶（用户指示）。
6. （v2 修订）连线多入线、按类型分组累积：text 多线按 `created_at` 拼接、
   ref/图片多线累积；DB 级仅 `UNIQUE(canvas_id, from_node, to_node)` 防同源
   重复平行线。v1 的「输入位唯一来源 `UNIQUE(canvas_id, to_node)` 顶掉」经
   可行性审阅废止——与多提示词拼接直接矛盾，且工程域「顶掉」实为前端
   unlink+link 而非 UNIQUE 天然实现。
7. 一切参考图先进资源库再引用，节点只记路径。
8. 生成失败不自动重试；结果不进撤销栈。
